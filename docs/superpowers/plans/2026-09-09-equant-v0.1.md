# equant v0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the first verified release of an AI-first Rust batch quantitative operator library with 60 public operators.

**Architecture:** One dependency-light crate exposes slice-based functions in six domain modules. Private rolling, smoothing, statistics, and validation primitives support equal-length typed results with explicit warmup, non-finite, error, and causality semantics.

**Tech Stack:** Rust 2021, MSRV 1.81, standard library runtime, `approx` and `proptest` for tests, Criterion for benchmarks, rustdoc for API documentation.

**Spec:** `docs/superpowers/specs/2026-09-09-equant-v0.1-design.md`

## Global Constraints

- Package name and library crate name are `equant`.
- Rust edition is 2021 and the declared minimum Rust version is 1.81.
- Version 0.1 has no runtime dependency on Python, TA-Lib, OpenXQuant, a DataFrame library, or another indicator library.
- Public calculations accept borrowed `f64` slices and return owned equal-length outputs.
- Continuous missing and warmup output is `f64::NAN`; non-finite required input resets recursive state.
- Public APIs return `IndicatorError` rather than panicking on invalid parameters or mismatched lengths.
- Version 0.1 contains no unsafe Rust and no implicit parallel execution.
- External publication and deployment are outside this plan.
