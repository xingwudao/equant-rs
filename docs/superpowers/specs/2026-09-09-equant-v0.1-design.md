# equant v0.1 Design

## Product Definition

`equant` is an AI-first, Rust-native, batch-oriented quantitative operator
library. Its primary user describes a quantitative calculation to an AI coding
agent, which generates a small Rust program using this crate. The user should
not need to learn Rust to obtain the performance, safety, and deployment
benefits of Rust.

Version 0.1 implements 60 batch operators inspired by the `equant-ttr` catalog.
The upstream project is a feature inventory and one numerical reference, not a
compatibility target. Public formulas and correct quantitative semantics take
priority over reproducing upstream output.

## Version 0.1 Scope

The release contains one crate named `equant`, organized into six public
modules:

- `trend`: `sma`, `ema`, `dema`, `wma`, `hma`, `zlema`, `alma`, `evwma`,
  `vwma`, `macd`, `adx`, `gmma`, `tdi`, `trix`, `dpo`, `vhf`, `kst`, and
  `po`.
- `momentum`: `rsi`, `cci`, `cmo`, `tsi`, `smi`, `wpr`,
  `ultimate_oscillator`, `roc`, `momentum`, `cti`, `rvi`, `dvi`, `stoch`,
  and `kdj`.
- `volatility`: `atr`, `tr`, `bollinger`, `keltner`, `donchian`, `pbands`,
  and `volatility`.
- `volume`: `obv`, `cmf`, `vwap`, `mfi`, `emv`, `clv`, `chaikin_ad`,
  `chaikin_volatility`, and `williams_ad`.
- `structure`: `zigzag`, `pivots`, `sar`, and `snr`.
- `transform`: `growth`, `adj_ratios`, `roll_sfm`, `aroon`, `td_setup`,
  `td_countdown`, `na_check`, and `lags`.

The following are explicitly excluded:

- streaming and incremental indicator APIs;
- Python, Pandas, NumPy, PyO3, and OpenXQuant integration;
- DataFrame, asset identifier, date, and multi-asset grouping abstractions;
- TA-Lib linkage or runtime dependencies on other indicator libraries;
- candlestick pattern recognition, Alpha 101, Alpha 191, factor processing,
  backtesting, data providers, broker connections, and order execution;
- publication to crates.io or deployment of any external artifact.

## Public API

Inputs are borrowed `&[f64]` slices. A single-output continuous operator returns
`Result<Vec<f64>, IndicatorError>`. A multi-output operator returns a named
public output struct whose fields are equal-length `Vec<f64>` values. Boolean
utilities return `Result<Vec<bool>, IndicatorError>`, and discrete counting
operators return `Result<Vec<i32>, IndicatorError>`.

Common calls contain no caller-visible generics, macros, or lifetime
parameters. Periods are `usize`. Every fallible public operator validates
periods, related parameter ranges, and equal input lengths before calculation.
It returns an error rather than panicking.

Examples:

```rust
let average = equant::trend::sma(&close, 20)?;
let strength = equant::momentum::rsi(&close, 14)?;
let range = equant::volatility::atr(&high, &low, &close, 14)?;
let result = equant::trend::macd(&close, 12, 26, 9)?;
println!("{}", result.histogram[result.histogram.len() - 1]);
```

The public error type has stable, actionable variants for zero periods,
invalid parameter ranges, mismatched input lengths, and insufficient
configuration. Empty and short valid inputs produce equal-length outputs,
usually all NaN, rather than errors.

## Numerical Semantics

Continuous outputs use `f64`. Leading warmup positions contain `f64::NAN`, and
every continuous output has the same length as its primary input. A rolling
window is valid only when all required values in that window are finite.
Recursive smoothing state resets after a non-finite required input and must
complete warmup again before emitting a finite value. All non-finite values,
including infinities, are treated as missing observations.

For multiple inputs, a row is valid only when all values required by the
operator are finite. Inputs are immutable. Implementations must not use unsafe
Rust in version 0.1.

Each operator documents its formula, seed convention, warmup length, parameter
domain, missing-value behavior, outputs, computational complexity, and
causality classification:

- `Causal`: output at index `t` uses only inputs through `t`.
- `ConfirmedWithDelay`: a historical event becomes known only after later
  observations.
- `Repainting`: later observations can change previously reported output.

`zigzag` is explicitly repainting. Causal operators must pass a prefix
invariance test: extending an input must not change its already-produced finite
prefix.

## Architecture

The crate is a single package. Public modules group operators by domain.
Private modules contain reusable rolling windows, smoothing, statistics, and
validation primitives. No universal public `Indicator` trait is introduced in
version 0.1.

Public functions allocate ergonomic, equal-length results. Private functions
may write into preallocated buffers to control intermediate allocations. The
crate does not enable implicit parallelism; callers can parallelize independent
assets, and a future higher-level package can add explicit multi-asset
execution.

Runtime dependencies are kept at zero unless an implementation requirement
cannot reasonably be met with the standard library. Development-only tools may
be used for property tests, approximate comparisons, fuzzing, and benchmarks.
The crate uses Rust edition 2021 and declares Rust 1.81 as its minimum supported
version.

## Correctness Strategy

Correctness has five layers:

1. Hand-verifiable unit tests cover private rolling, smoothing, and statistics
   primitives.
2. Every public operator has golden cases for normal, constant, monotonic,
   short, missing-value, and parameter-boundary inputs where applicable.
3. Property tests cover output length, documented ranges, scale or translation
   invariants, channel ordering, and causal prefix invariance.
4. Equivalent formulas are compared during development against independent
   references such as official TA-Lib, public literature, and `equant-py`.
   Reference packages do not become runtime dependencies.
5. Robustness tests exercise empty, malformed, non-finite, and random inputs
   and require panic-free behavior.

A disagreement with a reference is investigated, not automatically copied.
The accepted formula and difference are documented when multiple conventions
exist.

## Performance Strategy

All operators target linear time unless the documented formula inherently
requires more. Rolling extrema use monotonic queues, rolling sums use running
accumulators, and smoothing uses single-pass recurrences. Avoidable
per-observation allocation is prohibited.

Criterion benchmarks cover representative trend, momentum, volatility, volume,
and structure operators at 1,000, 100,000, and 1,000,000 observations. Claims in
the README must be reproducible and must not promise a speedup unsupported by
checked-in benchmark commands and environment details.

## Documentation And Discoverability

The English README is the canonical landing page and contains the phrases
`Rust quantitative finance`, `technical analysis indicators`, `batch market
data`, `algorithmic trading`, and `AI-generated Rust` naturally. It explains
the product boundary, installation, a runnable quick start, the full operator
catalog, correctness policy, benchmark command, and project status.

`README.zh-CN.md` provides the Chinese entry point. Crate metadata includes a
concise description, five relevant crates.io keywords, finance and algorithm
categories, repository URL, documentation URL, MIT license, and minimum Rust
version. Every public item has rustdoc, and every operator has at least one
compiling documentation example.

An `OPERATORS.md` catalog provides stable, searchable entries with name,
category, inputs, outputs, defaults, warmup, causality, and formula convention.
An `examples/quickstart.rs` program demonstrates a coherent OHLCV workflow.

## Acceptance Criteria

Version 0.1 is complete when:

- all 60 named public operators compile and are exported from the documented
  modules;
- all continuous outputs are equal length and obey the documented non-finite
  and warmup behavior;
- all parameter and input-length failures return `IndicatorError` without
  panics;
- every operator has formula documentation and direct tests;
- all causal operators pass prefix invariance checks where meaningful;
- `cargo fmt --check`, `cargo check --all-targets`, `cargo test --all-targets`,
  `cargo clippy --all-targets -- -D warnings`, and documentation tests pass;
- the quick-start example runs successfully;
- benchmarks compile and at least a smoke benchmark executes;
- README, Chinese README, operator catalog, license, contribution guide, and
  crate metadata are present;
- no release, publication, Python binding, or OpenXQuant artifact is created.
